# 成员 4 合入成员 5（2026-11-28）

目标分支：`feature/member5-evaluation-logging`。
合入来源为 `xhc`，提交 `fa1b5f7`。本次采用合并提交保留成员5和xhc双方历史。

本轮在成员 5 分支上补充了稳定冠军的有限探测策略：

- A、B、C 均在连续 4 个稳定轮次后允许一次探测；
- 探测最多比较 1 个候选、每候选 1 个 epoch，且 CPU 至少剩余 25%；
- 连续 2 次探测均未提升后冷却 8 个稳定轮次；
- 成功上线或发生普通数据驱动训练时重置探测失败序列；
- 只有实际生成候选并进入门控的探测才累计失败，决策到期但没有训练不计入；
- 决策层强制探测为 1 个候选、1 个 epoch，冷却期内不开放训练动作；
- 本轮出现退化或新增训练数据时，优先执行本轮训练，历史探测资格失效；
- 候选仍必须通过与父模型相同的成员 5 验证门控，策略层不能直接上线。

无新增训练数据且成绩未下降时，探测到期会给出 `finetune` 和
`adaptive_update(1,1)` 提示；未到期或处于冷却期时保持 `no_update`。
性能退化、明确新工况和真实新增数据仍走原有训练路径。

诊断日志的 `rows.new` 现在只表示本轮新增训练行；验证集行数单独记录在
`rows.validation`，`rows.new_known` 表示行差分是否可用。

策略版本升级为 `member4-champion-challenger-v4`，决策提示升级为
`member3-decision-v7`。稳定空闲轮在探测未到期或 CPU 低于 25% 时只允许
保持父模型或已验证回滚；探测回退也会保留合法的父模型 seed `0`。

原子目录/文件替换统一使用 Windows 瞬时占用重试：仅对 WinError 5、32、33
做短指数退避，其他权限或路径错误立即抛出。该逻辑覆盖阶段提交、轮次状态、
轮次记录和成员5审计写入。
