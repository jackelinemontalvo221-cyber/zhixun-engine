# 成员 4：工业模型训练与候选生成

本模块实现成员 4 的训练接口：

```python
train_candidate(bundle, decision, active, budget) -> CandidateModel | None
```

它从成员 1 验证过的当前父检查点继续训练，产生候选工业模型并返回真实
`checkpoint.npz` 字节。模块不负责漂移诊断、Qwen 调用、评测、上线或最终状态切换。

## 启用的动作

| 动作 | 数据与训练方式 |
| --- | --- |
| `no_update` | 不产生候选 |
| `adaptive_update` | 在预算内训练少量任务级候选，逐 epoch 验证并返回最佳 checkpoint |
| `finetune` | 从当前父检查点使用当前训练批次续训 |
| `retrain_full` | 从当前父检查点使用当前完整训练批次续训 |
| `retrain_recent` | 从当前父检查点使用当前批次末尾 `window_ratio` 比例的数据续训 |

`retrain_full` 不是重新初始化模型。所有训练动作都必须继承平台提供的父检查点。

`adaptive_update` 的决策参数为：

```json
{"max_candidates": 2, "max_epochs": 3, "seed": 42}
```

成员4根据数据包生成最多 `max_candidates` 个低成本计划，每个计划都从同一个
父检查点重新开始。每个训练 epoch 后都在公开验证集上评测，只保留该计划中
指标最好的 checkpoint，再在不同计划之间选择最终候选。候选仍必须经过成员5
的非回归门控才能上线。

当前默认计划：

| 任务 | 候选计划 | 选择指标 |
| --- | --- | --- |
| A | 全量1 epoch；全量最多20 epoch；类别平衡低学习率候选；可用时回放 | Macro-F1 |
| B | 结构化剪枝候选（24→8 个隐藏单元，最近50%数据，最多5 epoch，带最差轴承惩罚）；最近30%的1/3 epoch 权重-only 候选；全量1 epoch；低学习率/低 RUL 加权/增强/回放候选 | RMSE |
| C | 全局尾部最近20%最多8 epoch（逐 epoch 选优，可用当前训练集重拟合输入标准化）；结构化剪枝候选（32→24，最近20%，最多4 epoch）；全量最多8 epoch（member4 主候选）；低学习率/低 RUL 加权/增强/回放候选 | RMSE（gate-safe 优先） |

本地按轴承/unit 的对照实验（平台行、无 `meta`）：

| 任务 | 候选 | 平均 RMSE | 最差批次 RMSE |
| --- | --- | ---: | ---: |
| B | 父模型 | 681.16 | 1064.97 |
| B | 全局尾部 5 epoch | 630.43 | 1035.83 |
| B | **剪枝 24→8 + 最近50% + 5 epoch** | **459.76** | **692.93** |
| C | 父模型 | 52.87 | 163.96 |
| C | 最近20% + 2 epoch（原默认） | 52.22 | 153.68 |
| C | 最近20% + 8 epoch（新默认） | **51.78** | 159.24 |
| C | 剪枝 32→24 + 4 epoch | 51.87 | — |
| C | 两轮 SWA | 51.83 | 157.21 |

C 的验证曲线不是单调的（epoch 2 是 52.22，epoch 8 才是 51.78），所以 C 的候选
上限从 2 提到 8，按 member4 的规则“先保证 gate-safe，再按 RMSE 选”。C 不使用
B 的最差组/最差批次选择分数；分组和批次指标只记录、不参与选择。

**按组取窗口 + 分组平衡权重**在 B/C 都更差（B 平均 RMSE 升高 38-74、最差轴承
退化 44-83），因此只保留为可选能力，不进入默认候选组合。

所有候选都从同一个父检查点继续训练，任务、特征路径和类别保持不变。结构化剪枝
只从父模型迁移保留权重，并在 checkpoint meta 里记录 `migration`；组委会确认这
属于续训，不允许的是“用全套数据从头训练另一套模型替代 baseline”。

训练技巧（全部从父模型续训）：

| 技巧 | 作用 |
| --- | --- |
| 结构化剪枝 | 按 `w1/w2` 范数保留隐藏单元，迁移权重/Adam/归一化统计，meta 记录 `migration`；只作为候选，最差组惩罚用 0.25（权重-only 候选 0.5），由验证集决定是否采用 |
| 样本加权 | A 类别平衡；B/C 低 RUL 加权，分组平衡可用但默认不启用；只影响训练，不改 checkpoint |
| SWA | 逐 epoch 权重平均，输出仍是单个 checkpoint |
| 输入标准化重拟合 | C 候选可用当前训练投影重拟合 mean/scale（验证/隐藏数据不参与），与成员4一致 |
| 最差组审计 | 每个候选都记录最差绝对组（平台 worst 指标口径）、其相对父模型的增减，以及退化最多的组；最差绝对组退化时选择分数扣 0.5 |
| 最差批次选择 | 回归任务按成员5同口径计算 256 行一档的最差批次，选择分数 = 平均改善 + 0.2×最差批次改善；C 因此从 e1 改选 e2 |
| 审计成本 | 分组指标用 `np.bincount` 向量化；父模型验证预测每轮只算一次，候选预测与指标计算复用 |
| 父模型 anchor | 小新数据更新时对参数做近端约束（EWC-lite），防遗忘 |
| 特征增强 | 训练行 jitter/scale，输入 schema 不变 |
| ID 分组回退 | 平台没有 `meta` 时从 id 解析 bearing/unit/batch，用于组审计/验证 |
| 小新数据 light | `<0.5%` no_update；`0.5%–5%` 1×1 + replay/anchor；`>5%` 或退化才完整搜索 |
| 稳定轮探测 | 连续 3 轮 no_update 后，member2 给出一次 1×1 探测。B 的探测用最近 10% 尾部 1 epoch（实测 461.75→458.56，最差批次 689.85→672.68）；C 保留自己的 recent-selected 1 epoch |

训练状态目录还会保存：

| 文件 | 内容 |
| --- | --- |
| `members/training/replay.npz` | 有界、仅训练集、按类别/RUL分层采样的历史回放缓冲区 |
| `members/training/strategy_stats.json` | 各候选策略的历史平均提升和胜出次数 |
| `members/training/latest.json` | 最近一轮候选、逐 epoch 指标和选择结果 |
| `members/training/audit.jsonl` | 不可覆盖的历史候选审计 |

可选候选会根据历史策略统计重新排序；已证明长期无效的候选会降低优先级。

公开B验证集的初步对照：

| 策略 | 数据窗口 | epochs | RMSE |
| --- | --- | ---: | ---: |
| 父模型 | - | - | 681.16 |
| 普通近期更新 | 最近30% | 3 | 631.88 |

该表为历史对照。结构化剪枝在组委会确认后恢复：剪枝只迁移父模型权重、不从头
训练，并写入 `migration` 记录；候选始终要经过成员5门控。

## 安全约束

- 校验任务类型、输入维度、分类类别顺序和 active 检查点身份。
- 没有训练标签时拒绝训练。
- 续训必须沿用父检查点的随机种子。
- 不修改、不覆盖父检查点。
- 候选文件在临时目录生成，通过 `CandidateModel.checkpoint_bytes` 交给 Harness。
- 训练失败抛出 `TrainingError`，由外层保留当前模型。
- 每轮的候选计划、逐 epoch 指标、选中策略和失败原因写入
  `members/training/latest.json` 与 `audit.jsonl`。

## 接入

使用配置：

```bash
CONTEST_CONFIG=configs/harness.full.json
```

全系统配置中的训练组件为：

```json
{
  "train_candidate": "member4.trainer:CandidateTrainer"
}
```

`configs/harness.member4.json` 保留为成员四调试入口；它与正式总配置使用同一个
训练组件。

## 测试

```bash
python -m pytest -q tests/test_member4_trainer.py
```

测试覆盖真实 A/B/C 官方检查点、不更新、近期窗口、父检查点保护、哈希校验、
无标签、任务/维度/类别不匹配、seed 不一致和 CPU 预算不足。

## 当前限制

- 训练成本估算仍是保守开发值，后续需要用 2 核、4 GiB 沙箱下的 A/B/C 真实
  运行数据重新标定。
- `retrain_full` 使用当前训练 bundle；平台是否向当前容器提供更早历史训练数据，
  应以正式数据合同为准。
- 集成分支已切换到 SDK 1.0.5，并使用 `chunked-v1` 分块上传测试宿主。

## 成员5分支的稳定探测

稳定且无新增数据时，成员5执行层仅在探测到期且CPU至少剩余25%时允许1候选、1epoch。
连续两次实际探测被门控拒绝后冷却8轮，成功上线或普通数据驱动训练重置失败计数。
C题正常训练保留全量和近期数据最多8个epoch，并逐epoch选择候选。
